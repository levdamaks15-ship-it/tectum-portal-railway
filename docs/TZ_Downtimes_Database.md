# ТЕХНИЧЕСКОЕ ЗАДАНИЕ (ТЗ)
## Внедрение модуля «База простоев технолога», инлайн-классификации и экспорта в Google Таблицы

> **Назначение документа:** Данное ТЗ предназначено для передачи в новый диалог ИИ-агенту для пошаговой реализации функционала Базы простоев без риска поломки смежных модулей.  
> **Проект:** Tectum Enterprise MES / ERP (`tectum-portal-railway`).  
> **Исходная ветка с готовыми наработками:** `backup/downtimes-workspace-v1` (remote GitHub & local).  
> **Целевая архитектура:** Двухкабинетное разделение (Кабинет Мастера и Кабинет Главного Технолога).

---

## 1. Цель и бизнес-контекст

Разделить контур работы с простоями на предприятии между двумя ролями:
1. **Мастер смены:** Занимается **только фиксацией** инцидентов во время смены. Интерфейс мастера должен быть максимально легким, простым, без аналитических фильтров и сложных баз.
2. **Главный технолог (Монаев С. / `technologist`):** Занимается **аудитом, аналитикой, классификацией и отчетами**. Технолог получает полнофункциональный аналитический модуль **«База простоев»** с быстрым классификатором в 1 клик, расчетом потерь и выгрузкой в персональную Google Таблицу.

## 2. Архитектурное разделение кабинетов (Strict Role Boundary)

### 2.1. Кабинет Мастера смены (`/p/shymkent/w/xci/shifts` / `/cabinet/master`)
* **Доступные вкладки:**
  1. `Рапорт мастера` (основная форма сдачи смены)
  2. `Выполнение плана бригадами`
  3. `Сводка производства`
  4. `Журнал простоев` (только форма оперативного ввода смены)
  5. `Месячная сводка выработки`
* **Требования к «Журналу простоев» мастера:**
  - **Категорический запрет:** База простоев, Bento-фильтры по месяцам, поповеры классификации и сводные отчеты в кабинете мастера **ОТСУТСТВУЮТ (Zero DOM-Leak)**.
  - Форма быстрого ввода: Линия, Смена, Время начала, Время окончания.
  - **Прямой ввод времени (`inputmode="numeric"`):** Поля времени должны открывать крупную цифровую клавиатуру (0–9) на мобильных устройствах, без нативных барабанов и каруселей. Авто-двоеточие при вводе 2 цифр (`14` ➔ `14:`).
  - Карточка-тумблер «Остановка оборудования» (`is_equipment_downtime = true/false`).
  - Голосовой ввод описания (Gemini Speech-to-Text).
  - Таблица показывает **только простои текущей открытой смены**.

### 2.2. Кабинет Главного Технолога (`/cabinet/technologist` / роль `technologist`)
* **Доступные вкладки:**
  1. `Сводка производства`
  2. `Журнал простоев` (форма ввода при необходимости)
  3. **`База простоев`** ⭐ (Главный рабочий инструмент технолога)
  4. `Месячная сводка`
  5. `Аналитика`
* **Функционал вкладки «База простоев» технолога:**
  - **Bento-панель фильтров:**
    - Быстрые пресеты периода: `Сегодня`, `Вчера`, `Эта неделя`, `Этот месяц`.
    - Фильтр статуса: `Все записи (N)` и `⚠️ Требуют классификации (N)`.
    - Селектор линии (`Линия 1`, `Линия 2`, `Все линии`).
    - Селектор категории простоя.
    - Поисковая строка по оборудованию, узлу, мастеру и тексту описания.
  - **Режим 1: «Журнал классификации» (Интерактивная лента):**
    - Компактный `line-clamp` (2 строки) описания мастера с кнопкой «Развернуть...».
    - **Инлайн-классификатор в ячейке:** При клике на категорию открывается всплывающий поповер с 5 утвержденными категориями:
      1. `⚙️ Механические`
      2. `⚡ Энергетические`
      3. `🧪 Технологические`
      4. `🛠️ ТО и ППР`
      5. `⏸️ Остановки без простоев`
    - Выбор категории в 1 клик немедленно отправляет запрос на сервер, меняет бейдж строки и уменьшает счетчик «Требуют классификации».
    - Инлайн-тумблер `🛑 Стоп линии` / `⏸️ Без простоя`.
  - **Режим 2: «Сводный отчет по категориям»:**
    - Верхняя плашка KPI: План (т), Факт (т), Недопроизводство/Потери (т и тенге), Часы чистого хода оборудования.
    - 5 сворачиваемых разделов по категориям с суммарной длительностью (минуты, часы) и долей (%) от общего времени работы.
  - **Кнопка выгрузки в персональную Google Таблицу:**
    - Выгрузка отчета за выбранный период в выделенный документ предприятия.

## 3. Интеграция с Google Таблицами (Dedicated Spreadsheet)

* **Целевой документ:** «Сводная таблица простоев TECTUM»
* **Идентификатор таблицы:** `DOWNTIMES_SPREADSHEET_ID = "1Til9axXv7_U6TLsfYr3Cd4pKufuxnV8FY4F5QKfG5Qk"`
* **Формируемые листы (3 фирменных вкладки):**
  1. `Простои ЛФМ 1` — детализация остановок 1-й линии.
  2. `Простои ЛФМ 2` — детализация остановок 2-й линии.
  3. `Простои СВОД` — сводный расчет по категориям с формулами сумм, долей и KPI.
* **Технические требования к выгрузке:**
  - Вызовы Google API обязаны быть обёрнуты в механизм повторов `retry_google_api` (защита от 429 Rate Limit и 503).
  - Выгрузка сериализуется через мьютекс `_google_sync_lock` в `routers/common.py`.
  - Все ошибки логируются в `models.AuditLog(action="ERROR")` с предварительным `db.rollback()`.

## 4. Спецификация бэкенда (API Contract)

### 4.1. Модели и DTO (`schemas.py`)
```python
class DowntimeClassifyUpdate(BaseModel):
    category: Optional[str] = None
    node: Optional[str] = None
    department: Optional[str] = None
    is_equipment_downtime: Optional[bool] = None
```

### 4.2. Эндпоинты (`routers/downtimes.py`)
1. `GET /api/downtimes/feed`:
   - Параметры: `start_date`, `end_date`, `line`, `category`, `unclassified_only: bool`, `search: str`.
   - Возвращает список объектов простоев с полями мастера, длительности, категории и потерь.
   - Доступ: `technologist`, `admin`, `director`.
2. `PATCH /api/downtimes/{id}/classify`:
   - Вход: `DowntimeClassifyUpdate`.
   - Атомарно обновляет категорию, узел, службу и признак остановки.
   - Записывает действие в `models.AuditLog(action="CLASSIFY")`.
   - Запускает фоновую синхронизацию.
   - Доступ: `technologist`, `admin`. Мастерам доступ **запрещен (403 Forbidden)**.
3. `GET /api/downtimes/report-summary`:
   - Параметры: `start_date`, `end_date`, `line`.
   - Возвращает агрегированные KPI: чистые часы работы, суммарное время простоев по 5 категориям, проценты от фонда времени, потери в тоннах и тенге.
4. `POST /api/downtimes/export/google-sheets`:
   - Параметры: `start_date`, `end_date`.
   - Инициирует генерацию и заполнение выделенной Google Таблицы `DOWNTIMES_SPREADSHEET_ID`.
