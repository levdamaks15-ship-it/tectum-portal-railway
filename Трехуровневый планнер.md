# План реализации: Трёхуровневый Планнер (Недели, Службы ОГМ/ОГЭ, Дорожные карты), Подзадачи, Связи и Хэштеги

## 1. Обзор задачи и цели
Цель — трансформировать автономный планнер задач Tectum Engineering в мощную систему управления производственными задачами с 3 горизонтами планирования:
1. **⚡ Недельные спринты (Оперативный уровень):** Текущие оперативные задачи на 1 неделю + контроль долгов.
2. **🔧 Планы служб ОГМ и ОГЭ (Тактический уровень):** Планово-предупредительные ремонты (ППР), ревизии оборудования, электрика, механика, регламентные работы.
3. **🗺️ Дорожные карты и проекты (Стратегический уровень):** Масштабные проекты на месяцы/кварталы с ключевыми вехами (Milestones), связями между задачами и контролем общего прогресса.
4. **🏷️ Система хэштегов (#ОГМ, #ОГЭ, #ЛФМ, #Закупки...):** Быстрая сквозная классификация, автокомплит и фильтрация в 1 клик.
5. **🔗 Связи и подзадачи (Иерархия):** Возможность декомпозировать задачи Дорожной карты на этапы и подзадачи, связывать задачи зависимостями («Зависит от...»), автоматический пересчет прогресса родительской задачи.

## 2. Предлагаемые изменения

### 2.1. База данных и модели ([models.py](file:///d:/Antigravity_Project/tectum_portal_railway/models.py))

Расширение модели `Task` новыми полями:
- `task_type`: `'weekly'` (по умолчанию — недельная задача), `'service_plan'` (план ОГМ/ОГЭ), `'roadmap'` (дорожная карта / проект), `'milestone'` (этап проекта).
- `department_service`: `'ОГМ'`, `'ОГЭ'`, `'Технологи'`, `'ОТК'`, `'Общий'` (для задач служб).
- `parent_id`: `ForeignKey("tasks.id", nullable=True)` — связь подзадачи/этапа с родительским проектом или задачей.
- `depends_on_id`: `ForeignKey("tasks.id", nullable=True)` — задача-блокер (связь зависимости).
- `tags`: `String` (хранение тегов через запятую или JSON, например `#ОГМ, #ЛФМ, #Закупки`).
- `target_quarter`: `String` (например, `"Q3 2026"`, `"Q4 2026"`) — для долгосрочных дорожных карт.
- `progress`: `Integer` (0–100%) — для проектов/этапов дорожных карт (вычисляется автоматически на основе статуса дочерних подзадач или задается вручную).

В `lifespan()` в [main.py](file:///d:/Antigravity_Project/tectum_portal_railway/main.py) добавить безопасную миграцию `ALTER TABLE tasks ADD COLUMN IF NOT EXISTS ...` для PostgreSQL и SQLite.

### 2.3. Бэкенд API ([main.py](file:///d:/Antigravity_Project/tectum_portal_railway/main.py))

1. **Эндпоинт `GET /api/tasks`:**
   - Поддержка параметров: `task_type` (`weekly`, `service_plan`, `roadmap`, `all`), `department_service`, `tag`, `parent_id`.
   - Автоматический подсчёт дочерних задач: для каждой задачи возвращать `subtasks_count`, `subtasks_done_count`, `calculated_progress`, `parent_title`, `depends_on_title`.
2. **Эндпоинт `GET /api/tasks/tags`:**
   - Возвращает список всех существующих хэштегов в системе с количеством задач по каждому тегу (для облака тегов и автокомплита).
3. **Эндпоинт `GET /api/tasks/roadmaps`:**
   - Возвращает иерархическое дерево: Проекты дорожной карты $\rightarrow$ Этапы (Milestones) $\rightarrow$ Связанные задачи спринтов/служб со статусами и прогрессом.
4. **Эндпоинт `POST /api/tasks` и `PUT /api/tasks/{id}`:**
   - Автоматический парсинг хэштегов из текста (`title`), если пользователь ввёл `#тег` в поле формулировки.
   - Пересчёт прогресса родительской задачи при смене статуса дочерней задачи.

     * Индикатор зависимостей («Ожидает завершения: [TSK-12] Поставка кабеля»).
2. **Интерактивная панель хэштегов:**

   * Подсветка тегов цветными бейджами внутри текста задачи.
3. **Модальное окно задачи:**
   * Выбор горизонта: *⚡ Недельная задача*, *🔧 План службы (ОГМ/ОГЭ)*, *🗺️ Проект дорожной карты*.
   * Поле «Родительский проект / Этап» (выпадающий список активных проектов).
   * Поле «Зависит от задачи» (выбор блокирующей задачи).
   * Поле ввода тегов с быстрым выбором популярных тегов.
   * Блок «Подзадачи и этапы» прямо внутри карточки задачи.

## 3. План верификации

### Ручное и визуальное тестирование:
1. Создание проекта Дорожной карты (например, *"Модернизация дозатора цемента"* на Q3-Q4 2026).
2. Создание этапов внутри дорожной карты и подзадач для ОГМ и ОГЭ.
3. Установка связи зависимости (Подзадача 2 зависит от Подзадачи 1).
4. Проверка смены статуса подзадачи и автопересчета прогресс-бара родительского проекта.
5. Проверка работы хэштегов: ввод `#ОГМ #Срочно`, фильтрация по клику на тег в шапке.
6. Проверка отображения и адаптивности в мобильной версии и на десктопе.
