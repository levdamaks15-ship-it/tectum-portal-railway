# Производственные регламенты и учет завода Tectum

## 1. Сменный график и пары передачи смен
- **Часы смен завода (UTC+5):**
  - **«День»:** 08:00 – 19:00.
  - **«Ночь»:** 19:00 – 08:00.
- **Хронологический закон пар смен (Handover Pairs):**
  - Для смены **«День»** (08:00–19:00): дежурная смена — дневная дата `target_date`; сдавшая (предшествующая) — **ночная смена предшествующего дня** (`prev_entry.night_shift_group` для даты `target_date - 1 день`).
  - Для смены **«Ночь»** (19:00–08:00): дежурная смена — ночная дата `target_date`; сдавшая (предшествующая) — **дневная смена текущего дня** (`entry.day_shift_group` для даты `target_date`).
- **Развязка серверного времени:**
  - Запрещено вычислять сдающую смену по текущему часу сервера (`now.hour`), если клиент передает конкретную смену (например, мастер утром вносит рапорт за прошлую ночь). Эндпоинты графика сменности (`/api/checklists/schedule/today`) принимают явный параметр `shift: "День" | "Ночь"`.
- **Автовыбор в формах:**
  - При открытии рапорта селектор смены предвыбирает фактическую смену завода, а селектор мастера — дежурного мастера из графика сменности.

## 2. Поддержка нескольких продуктов и партий в смене (Переход продукции)
- **Уникальность записи рапорта:**
  - Запись в таблице `shifts` уникально идентифицируется набором: `(date, shift_name, line, product_name, batch_number)`.
- **Запрет перезаписи (Backend):**
  - При поиске существующей смены в БД (в эндпоинтах `POST /api/report` и `GET /api/shifts/by_params`) обязательно включать в фильтр поля `product_name` и `batch_number`. Если в течение смены произошёл переход на другую продукцию или сменился номер партии, создается новая независимая запись `Shift`, а не перезаписывается предыдущий рапорт.
- **Реакция интерфейса (Frontend):**
  - При изменении пользователем полей продукции (`#rep-product`) или номера партии (`#rep-batch`) фронтенд отправляет `onProductChange` с параметрами `product_name` и `batch_number` в query string. При `404 Not Found` форма очищает числовые показатели выработки для новой партии, сохраняя общие параметры слота.
- **Хронологическая сортировка партий:**
  - В SQLAlchemy-запросах `.order_by(...)` включать сортировку по `batch_number` перед `id`:
    - Убывающая: `models.Shift.batch_number.desc(), models.Shift.id.desc()`
    - Возрастающая: `models.Shift.batch_number.asc(), models.Shift.id.asc()`
- **Агрегация тонн (Backend Aggregation):**
  - При наличии нескольких рапортов за один слот `(date, shift_name, line)` **категорически запрещено** умножать общее число листов на средний вес одной партии или перезаписывать `tons` в цикле.
  - Обязательно аккумулировать фактические тонны всех рапортов в слоте:
    ```python
    total_tons = sum(r.lfm_sheets * get_product_finished_weight_kg(db, r.product_name) / 1000.0 for r in slot_reports)
    avg_weight = (total_tons * 1000.0) / total_sheets if total_sheets > 0 else 0
    ```

## 3. Три автономных журнала данных и гибридный fallback
1. **Производственные рапорты (`shifts`, `lfm_reports`, `batches`):**
   - Учет выработки ЛФМ, замесов, сбросов, дефектов дестакера (7 видов: Сдир, Плохой рез, Налип сверху, Сломан, Упал коробки, Не соотв. толщины, Кромка) и расхода сырья ЗО.
2. **Приход сырья (`raw_material_receipts`):**
   - Автономный складской журнал: `date`, `shift_name`, `line`, `master_id`, `timestamp`.
   - Запрещено создавать фиктивные записи в таблице `shifts` при сохранении прихода сырья!
3. **Журнал простоев (`downtimes`):**
   - Автономный журнал ремонтных событий: `start_time`, `end_time`, `duration`, `node`, `description`, `is_equipment_downtime`.
   - Запрещено создавать фиктивные записи в таблице `shifts` при сохранении простоя!
- **Гибридная обратная совместимость (Hybrid Fallback):**
  - Поле `shift_id` в `raw_material_receipts` и `downtimes` является `nullable=True`.
  - В моделях SQLAlchemy обязательны гибридные свойства-аксессоры:
    ```python
    @property
    def record_date(self):
        return self.date if self.date else (self.shift.date if self.shift else None)
    ```
  - Запросы к БД строятся через `outerjoin(models.Shift)` и `func.coalesce(models.Downtime.date, models.Shift.date)`.
- **Изоляция удаления в админке:**
  - Удаление смены (`admin_delete_shift`) удаляет **только** производственную запись. Связанные приходы и простои не удаляются, а отвязываются (`shift_id = None`) с сохранением даты, линии и смены.
  - Если после удаления прихода или простоя смена остается пустой («зомби-смена» без выработки и партий), она удаляется.

## 4. Фильтрация пустых смен (Phantom Shifts) в отчетах
- При формировании сводных таблиц (`get_report_summary`), дашбордов (`get_daily_report`, счетчик `total_shifts`), экспорте в Google Sheets и получении списков смен **строго исключать** пустые смены, у которых одновременно:
  - `plan_sheets == 0`
  - `lfm_sheets == 0`
  - `warehouse_gp == 0`
  - `zo_batches == 0`
  - `zo_submitted == False`
- *Важно:* Наличие записей о простоях (`downtimes`) или приходах сырья (`receipts`) **НЕ делает** смену рабочей.

## 5. Производственный план (План-факт) и Санитарный день
- **Фиксированные нормы:** Суточный план не вычисляется делением от месячного плана, а строится по утвержденным нормам производительности технологических линий.
- **Конвертация смен в дни (Shift to Days Calculation):**
  - В сутках ровно 2 смены («День» и «Ночь»).
- **Sanitary Day (Санитарный день):**
  - Каждый понедельник смена «День» является санитарной / технической (смена «С»), предназначенной для чистки и ППР. Учитывается без нарушения баланса производственного календаря.
- **Компонентная гидратация (Component-First Form Hydration):**
  - В модальных окнах с составными полями итоговая сумма вычисляется динамически из компонентов:
    `(valA > 0 || valB > 0) ? (valA + valB) : (parseFloat(record.total) || 0)`.
  - Функции пересчета (`calcLaprol`, `calcAdminLaprol`) доступны в `window`.

## 6. Синхронизация с Google Sheets и экспорт в SharePoint
- **Google Sheets:**
  - При синхронизации сводного отчета (`sync_report_to_google_sheets`) диапазон автофильтра (`setBasicFilter`) пересчитывается на актуальный `total_rows`.
  - Колонка дат (Колонка A) форматируется правилом `numberFormat: {type: "DATE", pattern: "dd.mm.yyyy"}` с выравниванием по центру (`CENTER`).
  - Единый шрифт: Arial, 9pt ко всем ячейкам.
- **SharePoint и Excel:**
  - При сохранении сменного рапорта запускается фоновая генерация Excel-отчёта и загрузка в SharePoint (папка `Reports`).
  - Данные оформляются как `ListObject` (форматированная таблица с чередующимися строками).
  - Обработка блокировки (HTTP 423): если файл заблокирован пользователем — сохранить локально и поставить задачу повтора `upload_sharepoint_report_retry`.
