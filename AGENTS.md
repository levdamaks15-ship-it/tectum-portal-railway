# АРХИТЕКТУРНЫЕ ЗАКОНЫ ПОРТАЛА «ТЕКТУМ» (BLUEPRINT ДЛЯ ИИ-АГЕНТОВ)

> Данный документ является высшим нормативным актом архитектуры корпоративного портала **«Тектум» (Tectum Enterprise MES / ERP / QMS)**.
> Любой ИИ-агент (Antigravity, Cursor, Claude Dev, Copilot), работающий методом **Vibe Coding**, обязан строго следовать этим 7 законам.
> Любое нарушение данных правил классифицируется как деградация архитектуры и подлежит немедленной отмене (Revert).

---

## 1. Контуры безопасности (Perimeter Separation)

Кодовая база физически разделена на две зоны:

| Контур | Пути в проекте | Правило доступа для ИИ |
|---|---|---|
| **Zone Red (Ядро платформы)** | `templates/core/`<br>`routers/auth.py`<br>`routers/tenant.py`<br>`routers/common.py`<br>`seed_tenant.py`<br>`database.py` | ⛔ **МОДИФИКАЦИЯ СТРОГО ЗАПРЕЩЕНА!**<br>ИИ-агенту запрещено вносить правки без явного разрешения пользователя: *«Разрешаю модификацию файла ядра [имя файла]»*. |
| **Zone Green (Продуктовые модули)** | `templates/modules/{module}/`<br>`routers/{feature}.py`<br>`static/modules/` |  **РАЗРЕШЕННАЯ ЗОНА.**<br>Здесь создается продуктовая логика, подключающаяся к ядру через `{% extends "core/base.html" %}` и фабрики роутеров. |

## 2. Семь Архитектурных Законов «Тектум»

### ЗАКОН 1. Неприкосновенность Ядра (Zero Core Modification)
Файлы ядра платформы содержат криптографическую защиту сессий, единую модель мультитенантности и системные заголовки W3C.
- **ЗАПРЕЩЕНО** изменять `templates/core/base.html`, `routers/auth.py`, `routers/tenant.py`, `routers/common.py`, `seed_tenant.py` при выполнении продуктовых задач (доработка смен, форм, отчетов, задач).
- Вся новая функциональность пишется строго в продуктовых модулях `templates/modules/` и роутерах доменов.

### ЗАКОН 2. Закон единственного каркаса и запрета дублирования шапки (Single Shell Law)
В системе существует ровно один базовый HTML-шаблон для сменно-управленческих экранов: `templates/core/base.html`. Он уже содержит теги `<!DOCTYPE html>`, `<html>`, `<head>`, `<body>`, сквозную шапку `<header>`, свитчер цехов Шымкента (ХЦИ, АГБ, ЛКЦ, СТМО, СКК), имя пользователя, кнопку выхода и Canvas-просмотрщик PDF.
- **ЗАПРЕЩЕНО** создавать в шаблонах модулей собственные теги `<!DOCTYPE html>`, `<html>`, `<head>`, `<body>`, `<header>` или `<nav>`.
- **ЗАПРЕЩЕНО** создавать в модулях собственные кнопки «Выйти» или локальные переключатели цехов.
- **ОБЯЗАТЕЛЬНО:** Каждый новый модуль сменного кабинета в `templates/modules/...` обязан начинаться со строки `{% extends "core/base.html" %}`, а вся верстка экрана помещается строго внутрь блока:
  ```html
  {% block content %}
      <!-- Разметка модуля -->
  {% endblock %}
  ```
- **ИСКЛЮЧЕНИЕ: Полноэкранные рабочие пространства (Full-Width Workspaces Exception):**
  - **Планнер задач (`/tasks`)** и **База знаний (`/docs`)** являются автономными полноэкранными рабочими пространствами (100% viewport width).
  - Их **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** зажимать в узкий контейнер `max-width: 1360px` или оборачивать во второй ярус общих вкладок цеха, что сплющивает 10 колонок таблицы задач и ломает жизненный цикл скриптов.
  - Они обслуживаются прямыми оптимизированными файлами (`static/tasks.html`, `static/docs.html`) с собственной эргономичной шапкой и прямыми кнопками перехода.

### ЗАКОН 3. Полный запрет на клиентское хранение состояния авторизации (Zero Client-Side Auth State)
Единственным источником истины о вошедшем пользователе является серверная сессия в базе данных (`user_sessions`), передаваемая в защищенной куке `__Host-tectum_session` (`HttpOnly`, `Path=/`, `SameSite=Lax`, `Secure`).
- **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** использовать `localStorage` или `sessionStorage` для чтения/записи `user`, `role`, `pin`, `token`, `session`, `plant_id`, `workshop_id`.
- **ЗАПРЕЩЕНО** делать на клиенте проверки вида `if (!localStorage.getItem('user')) window.location = '/login'`.
- **ОБЯЗАТЕЛЬНО:** Метаданные текущего рабочего контекста считываются из серверных data-атрибутов:
  ```javascript
  const plantId = document.body.dataset.plantId;       // "shymkent"
  const workshopId = document.body.dataset.workshopId; // "xci", "lkc" и т.д.
  ```

### ЗАКОН 4. Обязательный мультитенантный роутинг в URL (Mandatory Tenant-Scoped Routing)
Активный завод и цех определяются **исключительно путем URL**: `/p/{plant_slug}/w/{workshop_slug}/{module}`. Это гарантирует изоляцию вкладок браузера (Multi-Tab Safety).
- **ЗАПРЕЩЕНО** сохранять выбранный пользователем завод или цех в `request.session['plant_id']` или мутабельной Cookie.
- **ЗАПРЕЩЕНО** создавать изолированные рабочие эндпоинты в обход контекста цеха.
- **ОБЯЗАТЕЛЬНО:** Все адреса страниц строятся по единому стандарту:
  - `/p/shymkent/w/xci/shifts` (Смены ХЦИ)
  - `/p/shymkent/w/lkc/shifts` (Смены ЛКЦ)
  - `/p/shymkent/w/agb/shifts` (Смены АГБ)
  - `/p/shymkent/w/stmo/shifts` (Смены СТМО)
  - `/p/shymkent/w/skk/shifts` (Сортировка СКК)
  - `/p/shymkent/w/xci/tasks` (Планнер задач)
  - `/p/shymkent/w/all/docs` (База знаний)

### ЗАКОН 5. Изолированный доступ к БД и обязательный workshop_id / plant_id (Scoped DB Law)
Каждый создаваемый производственный объект (смена, простой, задача, дефект) обязан принадлежать конкретному цеху и заводу.
- **ЗАПРЕЩЕНО** создавать новые производственные таблицы без колонок `plant_id` (default: 'shymkent') и `workshop_id`.
- **ОБЯЗАТЕЛЬНО:** Для текстовых полей свободного ввода (заметки, причины простоев, комментарии) всегда использовать тип `Text` (исключение переполнения `VARCHAR(255)`).
- **ОБЯЗАТЕЛЬНО:** Любые выборки данных цеха обязаны содержать явную фильтрацию по `workshop_id`.

### ЗАКОН 6. Бесшовная навигация и жизненный цикл скриптов (Hypermedia & View Transition Law)
Переходы между экранами управляются автоматически библиотекой HTMX (`hx-boost="true"`) и браузерным слиянием кадров CSS `@view-transition`.
- **ЗАПРЕЩЕНО** создавать промежуточные Splash-экраны и полноэкранные загрузочные спиннеры при смене экранов.
- **ЗАПРЕЩЕНО** использовать `window.onload` или `DOMContentLoaded` для инициализации логики модулей в JS, так как при быстрых переходах через HTMX страница не перезагружается целиком.
- **ОБЯЗАТЕЛЬНО:** Все обработчики событий регистрируются через **делегирование на уровне документа**:
  ```javascript
  document.addEventListener('click', (e) => {
      const btn = e.target.closest('.my-action-btn');
      if (btn) { /* логика */ }
  });
  ```

### ЗАКОН 7. Защищенный стриминг документов и регламентов (Authenticated Media Law)
Внутренние технологические регламенты, чертежи и инструкции предприятия не должны быть доступны по прямым статическим ссылкам.
- **ЗАПРЕЩЕНО** сохранять производственные PDF в общедоступную папку `/static/`.
- **ЗАПРЕЩЕНО** использовать `<iframe src="...pdf">` или `<embed>`, вызывающие сбои на мобильных устройствах iOS/Android.
- **ОБЯЗАТЕЛЬНО:** Для открытия любого PDF в верстке используется стандартный атрибут ядра:
  ```html
  <button type="button" data-open-pdf="/api/files/{{ doc.id }}/stream" data-pdf-title="{{ doc.title }}">
      <i class="fa-solid fa-file-pdf"></i> {{ doc.title }}
  </button>
  ```
  Ядро `base.html` автоматически перехватит клик, загрузит поток с сессионной кукой через типизированный массив `Uint8Array` и отрендерит его на HTML5 `<canvas>` без белых экранов и системных сбоев.

### ЗАКОН 8. Изоляция веток и чистота коммитов (Branch Isolation & Safe Commit Law)
- **ЗАПРЕЩЕНО** вести разработку крупных архитектурных фаз или экспериментальных функций напрямую в ветке `main`. Вся разработка ведется в изолированных ветках `feature/*`.
- **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** использовать слепые команды `git add .`, `git add -A` или `git commit -a`, способные затянуть в коммит нецелевые черновики и архивы. Коммитятся строго целевые файлы домена.
- **ЗАПРЕЩЕНО** выполнять `git push` без прямого подтверждения от пользователя.
